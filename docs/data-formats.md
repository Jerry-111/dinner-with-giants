# Data formats

Every file an agent hands to another agent, or to `tools/sim.py`, has a fixed shape. This page is the reference; JSON Schemas live in `schemas/`. Field names are English in every language; free-text values may be in the run's language.

Conventions:

- IDs: personas `P1…Pn` in examples (any `[A-Z][A-Za-z0-9]*` works: `H2`, `Q7`); baselines `Z1`, `Z2`; options are whatever the rubric defines (`O1…`, `D01…`); cruxes and tables `X1…`; levers `L1…`; named questions `Q1…`; evidence-brief facts `F1…`.
- Post IDs: `<round>/<table>/<persona>`, for example `A/X3/P5`, `B/X1/P2`, `OT/X2/P4`.
- Scores: integers on the rubric's scale (default 0–10). `null` means "no judgment" and is always allowed.
- Labels for `basis`: `quoted | synthesized | inferred` (Chinese runs may use `原话 | 归纳 | 推断`; the tooling accepts both).
- Verdicts: `accept | reject` (Chinese: `接受 | 不接受`). Older runs also used `partial | 部分接受`; the tooling counts it but templates no longer ask for it.
- Search results: `supports | refutes | unclear` (Chinese: `支持 | 反驳 | 不清楚`).
- Every persona-authored Markdown file starts with the simulation notice (see `AGENTS.md`). `tools/sim.py lint` checks it.
- Filenames are ASCII. Interjections are `<ID>_interjection.md`; overtime posts are `<turn>_<ID>.md`.

## Run directory

```
workspace/runs/<YYYY-MM-DD>_<slug>/
  scope.md               # run brief (template: templates/run/scope.md)
  rubric.json            # pre-registered; frozen once R1 is in
  RUN_METADATA.md        # timeline, inputs, independence, limits
  evidence/brief.md      # shared facts F1…, each with a source
  evidence/errata.md     # fact-check ① corrections (and errata_B.md for ②)
  r1/<ID>.json, r1/<ID>.md
  baselines/Z1_r1.json, Z1_r1.md, Z1_r3.json, …
  cruxes.json, tables.json
  board/A/<table>/<ID>.md
  board/A/INDEX.md       # generated: one-line claim per opening post
  board/B/<table>/<ID>.md, board/B/<table>/<ID>_interjection.md
  board/C/<table>/<ID>.md
  board/overtime/<table>/<turn>_<ID>.md
  board/summary/<table>.md        # persona-facing scribe notes
  board/summary_full/<table>.md   # full scribe notes (who persuaded whom)
  r3/<ID>.json, r3/<ID>.md
  judge/<table>.md, judge/scores_<batch>.json, judge/scores.json
  audit.md               # fact-check ③
  digests/<area>.md      # optional per-area digest (protocol/05_digest.md)
  summary.json, summary.md        # generated by `tools/sim.py aggregate`
  report.md, review.md
  reader/page.md         # reader pack: one page for the user (protocol/07_reader_pack.md)
```

Self-check budgets default to: R1 3 searches; each debate round (B, C) 2; each overtime turn 1;
R3 1. A run can override them in `scope.md`.

Small runs may skip overtime, judges or the digest; `RUN_METADATA.md` says what was skipped.

A fidelity test (`protocol/11_fidelity_test.md`) is its own run folder:

```
workspace/runs/<YYYY-MM-DD>_fidelity/
  RUN_METADATA.md
  cards_pre/<ID>.yaml    # cards rebuilt from sources dated on or before the cutoff
  questions.md           # questions that do not leak the answers
  answers_key.md         # real post-cutoff statements and sources; only the grader reads it
  responses/<ID>_<group>.md   # group = persona | name_only | analyst
  grading.md             # blind grades per question and the persona − name-only gap
```

## `rubric.json`

```json
{
  "version": "2026-11-14",
  "note": "Pre-registered. Not edited after R1 submissions.",
  "options": {"O1": "Join a large research lab", "O2": "Join a startup", "O3": "Start a PhD"},
  "short_options": [],
  "dimensions": {
    "upside": "If it works, how much does it matter in 10 years",
    "learning": "How much durable skill and judgment it builds",
    "timing": "Is now a good moment to enter",
    "fit": "Fit with the user's stated interests and constraints"
  },
  "scale": {"min": 0, "max": 10},
  "overall": "The persona's own overall score, weighted by the persona's own values; not the average of dimensions.",
  "levers": {"L1": "…", "L2": "…"},
  "lever_allocation": "Split 100 points across L1…: which factors will most decide the outcome.",
  "named_questions": {"Q1": "…", "Q2": "…"},
  "conditional_questions": {
    "Q2": {"question": "Under which conditions would you say yes to …?", "conditions": {"C1": "…", "C2": "…"}}
  },
  "pairwise": [["O1", "O2"], ["O2", "O3"]],
  "weight_sets": {
    "equal": {"upside": 0.25, "learning": 0.25, "timing": 0.25, "fit": 0.25},
    "learning_heavy": {"upside": 0.2, "learning": 0.4, "timing": 0.1, "fit": 0.3}
  },
  "personas": {
    "P1": {"name": "Persona display name", "aliases": ["Short name"]},
    "P2": {"name": "…", "aliases": []}
  },
  "baselines": ["Z1"],
  "groups": {"lens A": ["P1", "P3"], "lens B": ["P2", "P4"]},
  "not_independent": [["P1", "P3"]],
  "seating": {"table_size": [4, 6], "seats_per_persona": 2},
  "r1_requirements": {"paths_for_user": [2, 3], "cruxes": 3},
  "forbidden_words": ["discount", "打折", "折扣", "减权"],
  "aggregation": {
    "primary": "Per option: median, IQR, min, max of persona `overall`. Sort by median; ties go to the smaller IQR.",
    "no_headcount_as_evidence": true,
    "no_weighting_by_persona": true,
    "no_extremizing": true,
    "sensitivity": "Flag options whose rank moves 3+ places across weight sets.",
    "sensitivity_threshold": 3,
    "baselines": "Reported separately; never pooled into the medians."
  }
}
```

Optional keys: `aggregation.sensitivity_threshold` (integer, default 3), `short_options` (options that may carry only `overall` and `one_line`), `levers`, `lever_allocation`, `named_questions`, `conditional_questions`, `pairwise`, `weight_sets`, `groups`, `not_independent`, `seating`, `r1_requirements`, `forbidden_words`. When a key is absent, the matching check or table in `summary.md` is skipped.

## R1 and R3 submissions: `r1/<ID>.json`, `r3/<ID>.json`, `baselines/<Z>_r1.json`

```json
{
  "id": "P1",
  "name": "Persona display name",
  "round": "R1",
  "notice": "Simulation based on public material; not the person's own words.",
  "options": {
    "O1": {
      "upside": 7, "learning": 6, "timing": 5, "fit": 8,
      "overall": 7,
      "confidence": "low|medium|high",
      "basis": "quoted|synthesized|inferred",
      "one_line": "Why this score, in one line",
      "late_modes": "Ways of taking part that are already too late, and why; or null",
      "conflict": "The persona's own interest in this option; or null"
    }
  },
  "levers": {"L1": 40, "L2": 60},
  "lever_reason": "…",
  "questions": {"Q2": {"position": "for|against|conditional", "score": 6, "condition": "…"}},
  "conditions": {"Q2": ["C1", "C3"]},
  "paths_for_user": [
    {"name": "…", "options": ["O1"], "next_12_months": "…", "why": "…", "wrong_signal": "…"}
  ],
  "cruxes": [
    {"question": "…", "my_position": "…", "would_change_if": "An observable fact", "options": ["O2"]}
  ],
  "taste_advice": "…",
  "pairwise": [{"a": "O1", "b": "O2", "pick": "O1", "why": "…"}],
  "web_searches": [
    {"query": "…", "url": "…", "published": "YYYY-MM-DD", "sentence": "≤15 English words, verbatim", "for_claim": "O2", "result": "supports|refutes|unclear"}
  ]
}
```

Rules checked by `tools/sim.py check r1|r3`:

- every rubric option is present (short options may be `{"overall": n, "one_line": "…"}`);
- scores are integers within the scale, or `null`;
- if the rubric has `levers`, the allocation sums to exactly 100;
- `paths_for_user` length and (R1 only) `cruxes` length follow `r1_requirements`;
- every rubric `pairwise` pair has a pick;
- R3 has `changes`.

R3 adds:

```json
{
  "round": "R3",
  "changes": [
    {"option": "O2", "from": 6, "to": 5, "because": "B/X1/P3 point 2", "argument_restated": "The argument in my own words", "why": "…"}
  ],
  "held_despite": [{"post": "B/X1/P4", "why": "Accepted in text, score unchanged, because …"}],
  "still_disagree": "… or null",
  "learned": "… or null",
  "searches": []
}
```

Baselines use the same shape with `"name": "Baseline analyst"` and `conflict: null` everywhere.

## `cruxes.json`

```json
{
  "cruxes": [
    {
      "id": "X1",
      "question": "A question people disagree on and facts can move",
      "why_it_matters": "Which options' order it changes",
      "options": ["O1", "O2"],
      "sides": [
        {"label": "…", "position": "…", "members": ["P1", "P3"]},
        {"label": "…", "position": "…", "members": ["P2", "P4"]}
      ],
      "evidence_needed": "What fact would settle it"
    }
  ],
  "open_questions": [{"question": "…", "asked_by": ["P2"], "why": "…"}]
}
```

## `tables.json`

```json
{"tables": [{"id": "X1", "crux": "X1", "members": ["P1", "P2", "P3", "P4"], "why": {"P1": "Why this seat; 'observer' if no stake"}}]}
```

`tools/sim.py tables` checks: table sizes within `seating.table_size`; every persona has exactly `seating.seats_per_persona` seats; every table has members on at least two sides of its crux; a `not_independent` group is never the only representation of one side.

## Debate posts

Markdown body, then one fenced `json` block at the end.

Header (first four lines of every post):

```
# X1 · B exchange · Persona display name (P3)
> Stance: <card.stance_line>
> Interests: <card.interest_line>
> Simulation based on public material; not the person's own words.
```

Closing JSON by round:

```json
{"responses": [{"to": "P2", "post": "A/X1/P2", "point": "The specific point", "verdict": "accept|reject", "why": "…"}],
 "source_challenge": [{"to": "P2", "post": "A/X1/P2", "claim": "…"}],
 "question_to": "P2",
 "retracted": [{"post": "A/X1/P3", "claim": "…"}],
 "intended_moves": {"O2": -1},
 "searches": []}
```

- A: `{"searches": []}` is enough.
- B and interjections: `responses`, `source_challenge`, `question_to`, `searches`.
- C: `responses`, `retracted`, `intended_moves`, `searches`.
- Overtime: `responses`, `retracted`, `searches`.

## Judge scorecards: `judge/scores_<batch>.json`

```json
{"posts": {"B/X1/P3": {"claim_clear": 4, "evidence_holds": 3, "answers_strongest": 4, "source_independent": 2, "flags": ["source_challenged"]}}}
```

Scores 1–5; `answers_strongest` is `null` for A posts. Flags: `not_an_argument`, `social_reason`, `retracted`, `source_challenged`, `experience_unverified`. The orchestrator merges batches into `judge/scores.json`.

## Persona folder

```
personas/<ID>_<slug>/
  dossier.md      # sections A–I (templates/persona/dossier.md)
  views.md        # domain views and prediction record
  conversation.md # optional: simulated conversation with the user
  card.yaml       # templates/persona/card.yaml
  sources.csv     # templates/persona/sources.csv; later versions add sources_v<N>.csv
```

`sources.csv` columns, in order:

```
evidence_id,claim,type,author_or_org,source_title,url,published_date,accessed_date,source_family,supports_or_challenges,limitations
```

## `summary.json` (generated)

Produced by `tools/sim.py aggregate`; `summary.md` is the human-readable view. Reports quote numbers from `summary.md` only. Keys: `n_r1`, `n_r3`, `overall_r1`, `overall_r3` (per option: `n, median, q1, q3, iqr, min, max`), `rank_r1`, `rank_r3`, `groups_r3`, `weighted`, `sensitivity_flips`, `moves`, `n_changed_scores`, `levers_r1`, `levers_r3`, `questions_r1`, `questions_r3`, `conditions`, `pairwise`, `baselines`, `persona_minus_baseline`, `verdicts`, `n_searches_in_debate`, `persuaded_by`, `empty_concessions`, `intent_vs_actual`, `source_challenges`, `retracted`, `judge`.
