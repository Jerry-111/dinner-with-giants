# R1: independent scoring

`<run>` = this run's folder. First read `<run>/scope.md`, `<run>/rubric.json`,
`<run>/evidence/brief.md`, and `<run>/evidence/errata.md` if it already exists. At this step you
cannot see anyone else's judgment.

Write in the run's language (set in `scope.md`). Every markdown file you write starts with the
simulation notice; `tools/sim.py lint` checks this.

## Submit two files

### 1. `<run>/r1/<ID>.json`

UTF-8, valid JSON (check with `python3 -m json.tool` after writing). Scores are integers on the
rubric's scale (default 0–10); write `null` for no judgment.

```json
{
  "id": "<ID>",
  "name": "<persona display name>",
  "round": "R1",
  "notice": "Simulation based on public material; not the person's own words.",
  "options": {
    "<O1>": {
      "<dimension>": 6,
      "overall": 4,
      "confidence": "low|medium|high",
      "basis": "quoted|synthesized|inferred",
      "one_line": "Why this score, in one line",
      "late_modes": "Ways of taking part that are already too late, and why; or null",
      "conflict": "Your own interest in this option; or null"
    }
  },
  "levers": {"<L1>": 0},
  "lever_reason": "One or two sentences",
  "questions": {"<Q>": {"position": "for|against|conditional", "score": 0, "condition": "..."}},
  "conditions": {"<Q>": ["<C1>"]},
  "paths_for_user": [
    {"name": "...", "options": ["<O1>"], "next_12_months": "...", "why": "...", "wrong_signal": "..."}
  ],
  "cruxes": [
    {"question": "...", "my_position": "...", "would_change_if": "An observable fact", "options": ["<O1>"]}
  ],
  "taste_advice": "...",
  "pairwise": [{"a": "<O1>", "b": "<O2>", "pick": "<O1>", "why": "..."}],
  "web_searches": []
}
```

Rules checked by `tools/sim.py check r1`:

- Every option in `rubric.json` `options` needs an entry; options listed in `short_options` may
  contain only `overall` and `one_line`, the rest `null`.
- If `rubric.json` defines `levers`, the allocation must sum to exactly 100.
- `paths_for_user` and `cruxes` counts follow `rubric.json` `r1_requirements`.
- Every pair in `rubric.json` `pairwise` gets a pick; never leave one blank. Score only the
  options you can actually judge — write `overall: null` for the rest.
- For each `rubric.json` `conditional_questions` entry, fill `conditions` with whichever listed
  conditions would flip your answer; an empty list is fine, explained in the md.
- **Score your honest judgment. Never discount your own score because you have a stake in an
  option** — interests are shown, never used as a discount (`protocol/03_debate_tables.md`); put
  the stake in `conflict` instead.
- Self-checks: up to 3, only for claims you plan to cite, logged in `web_searches` (query, url,
  published, sentence ≤15 English words verbatim, for_claim, result). Private by default.

### 2. `<run>/r1/<ID>.md` (≤12 KB)

Top line: the simulation notice. Then, in order:

1. **One-line overall verdict.**
2. **Option tiers.** Top, middle, bottom, one reason each; expand only the options with the most
   disagreement potential or where you're most confident.
3. **Named questions**, answered directly, one by one (`rubric.json` `named_questions` and
   `conditional_questions`).
4. **Claims to test** (`scope.md`), addressed by the option(s) they bear on; attribute each
   claim's source the way `scope.md` does (for example "a friend," "a mentor") — never a real
   name.
5. **Paths for the user** — the content of `paths_for_user` above, in prose, including how the
   user's own stated background makes a path more or less valuable.
6. **One piece of taste advice**, plus the experience that makes you believe it.
7. **Your own interests and blind spots**, pulled from `card.yaml`, and how they could be
   shaping the judgments above.
8. **Where this judgment is most likely wrong.**
9. **Self-checks performed**, if any: URL, date, one line.

Sections 2-6 each need at least one experience argument: what happened (cite the dossier
section, with its evidence label), what it taught you, why it applies here, and where the
analogy might break. Label every judgment `[quoted]`, `[synthesized]`, or `[inferred]`.
